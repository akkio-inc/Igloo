Architecture

How it works

One Go server in front of an embedded DuckDB, with tables in Apache Iceberg on your object storage.

  • igloo (this repository, Go) accepts Postgres and Arrow Flight SQL connections, checks each statement against the user’s role and grants, and runs it on an embedded DuckDB attached to the catalog. On start it sets up the catalog and warehouse itself, so every deployment works the same way.
  • Lakekeeper is the Iceberg REST catalog: it tracks tables, schemas and snapshots. Only Igloo talks to it; other engines use Igloo’s own Iceberg REST endpoint (port 8181), which checks their requests against the same users and grants and passes them on.
  • PostgreSQL stores the catalog’s metadata and Igloo’s users.
  • Object storage holds the table data as Parquet files.

Every component uses a permissive open-source license (Apache 2.0, MIT or the PostgreSQL License), except two libraries under the LGPL 2.1 inside DuckDB’s extensions: GEOS in the spatial extension (see media analytics), and MariaDB Connector/C, the MySQL client library, in the mysql extension.
