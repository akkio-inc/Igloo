Each feature links to its documentation. Limitations in 1.0 lists what isn't done yet.

SQL and tables

CREATE TABLE dev.orders CLONE prod.orders
  AT (TIMESTAMP => now() - INTERVAL 1 DAY);

  • Iceberg tables

    CREATE TABLE, CREATE TABLE AS, INSERT, UPDATE, DELETE, MERGE, schemas, views, comments, and time travel.

  • Zero-copy clones

    A copy of production to develop and test against, made in seconds without copying any data. Iceberg branches and tags are supported too.

  • Media analytics

    HLL and theta sketches for deduplicated reach and audience overlap; geometry and H3 functions for DMA, zip code and store-radius reporting.

  • Connections to other databases

    Query PostgreSQL and MySQL databases in place, read-only, and join them with Iceberg tables.

Security and governance

role in sessionemailpii_readerann@example.comanalystsha256(email)

  • Users, roles and grants

    SCRAM-SHA-256 passwords, built-in roles, and custom roles with grants on schemas and tables, all managed in SQL.

  • Single sign-on

    Okta, Microsoft Entra ID, Google Workspace or any OpenID Connect provider; access tokens and service accounts.

  • Row access and masking policies, and tags

    Show each team only its clients' rows, and mask identifiers for everyone not allowed to see them.

  • Erasure of personal data

    One statement deletes a person's rows from every table whose columns are tagged with their identifiers, for GDPR and CCPA requests.

Data in and out

raw.campaignsraw.impressionsmedia.delivery

  • Loading and scheduling

    COPY INTO, pipes that load new files as they land, tasks on a cron or interval schedule, and materialized views.

  • Alerts and notifications

    Alerts run a query on a schedule and notify Slack, Microsoft Teams, email and webhooks when it returns rows.

  • Delta Sharing

    Share tables with clients and partners through the open protocol, and query partners' shares as external tables.

  • Other engines

    Spark, Trino, PyIceberg, Databricks and Snowflake read and write the tables through Igloo's Iceberg REST catalog, subject to Igloo's grants.

Operations

max_concurrent_statements = 4

  • Data catalog

    Search, owners and descriptions, size and freshness, usage and table-level lineage from the query history.

  • Workload management

    Query tags, per-client usage and estimated cost, per-role limits, and compute pools.

  • Scale to zero

    A small gateway stops Igloo's machines or pods when nobody uses them and starts them when a client connects.

  • Distributed execution

    A query over a very large table runs in parts on worker machines that Igloo starts when it needs them.
