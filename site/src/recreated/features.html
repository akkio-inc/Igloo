Iceberg tables
CREATE TABLE, CREATE TABLE AS, INSERT,
UPDATE, DELETE, MERGE, schemas, views,
comments, and time travel.
Media analytics
HLL and theta sketches for deduplicated reach
and audience overlap; geometry and H3
functions for DMA, zip code and store-radius
reporting.
Zero-copy clones
A full copy of production to develop and test
against, made in seconds without copying data;
and Iceberg branches and tags.
Connections to other databases
Query PostgreSQL and MySQL databases in
place, read-only, and join them with Iceberg
tables.
Users, roles and grants
SCRAM-SHA-256 passwords, built-in roles,
and custom roles with grants on schemas
and tables, all managed in SQL.
Single sign-on
Okta, Microsoft Entra ID, Google Workspace
or any OpenID Connect provider; access
tokens and service accounts.
Row access and masking policies, and
tags
Show each team only its clients' rows, and
mask identifiers for everyone not allowed to
see them.
Erasure of personal data
For GDPR and CCPA requests: one
statement deletes a person's rows from
every table whose columns are tagged with
their identifiers.
Loading and scheduling
COPY INTO, pipes that load new files as they
land, tasks on a cron or interval schedule,
and materialized views.
Alerts and notifications
Alerts run a query on a schedule and notify
Slack, Microsoft Teams, email and
webhooks when it returns rows.
Delta Sharing
Share tables with clients and partners
through the open protocol, and query
partners' shares as external tables.
Other engines
Spark, Trino, PyIceberg, Databricks and
Snowflake through an Iceberg REST catalog,
under Igloo's grants.
Data catalog
Search, owners and descriptions, size and
freshness, usage and table-level lineage
from the query history.
Workload management
Query tags, per-client usage and estimated
cost, per-role limits, and compute pools.
Scale to zero
A small gateway stops Igloo's machines or
pods when nobody uses them and starts
them when a client connects.
Distributed execution
A query over a very large table runs in parts
on worker machines that Igloo starts when it
needs them.

CREATE ROW ACCESS POLICY client_rows AS (cid VARCHAR) RETURNS BOOLEAN ->
EXISTS (SELECT 1 FROM governance.client_access a
WHERE a.client_id = cid AND is_role_in_session(a.role_name));
ALTER TABLE marts.impressions ADD ROW ACCESS POLICY client_rows ON (client_id);
CREATE MASKING POLICY mask_pii AS (val VARCHAR) RETURNS VARCHAR ->
CASE WHEN is_role_in_session('pii_reader') THEN val ELSE sha256(val) END;
CREATE TAG pii ALLOWED_VALUES 'email', 'device_id';
ALTER TAG pii SET MASKING POLICY mask_pii;
ALTER TABLE marts.impressions ALTER COLUMN email SET TAG pii = 'email';
